# 老字号叙事工坊作品运行录屏脚本与演示流程

## 一、演示目标

在一段完整的录屏中，展示老字号企业新媒体运营人员的真实工作过程：把分散的品牌历史、产品资料和受访内容整理为可追溯事实，生成多平台内容，检查事实与宣传风险，修改问题语段，最后完成人工审核并导出成果。

推荐成片时长：5分30秒至6分钟。  
录制比例：16:9，1920×1080或1440×900。  
浏览器缩放：100%。  
演示品牌：鲁香斋（模拟品牌），明确说明为原型演示数据。

## 二、演示场景

鲁香斋准备围绕“一块枣泥酥里的山东老味道”制作一组节令礼盒内容，目标平台为小红书，同时需要形成内容日历和短视频脚本。运营人员需要保证年份、工序、产品名称和品牌身份都来自资料，不能补写未证实的荣誉或功效，并需要留下人工审核记录。

## 三、演示流程介绍

录屏按“输入—处理—输出”的顺序展开。输入阶段展示品牌基本信息、品牌资料、受访原话和创作要求；处理阶段展示事实提取、来源定位、内容生成、风险检查、逐段修改和证据门禁；输出阶段展示四份内容成果、广告词候选、内容护照、协作审核记录和导出文件。视频不停留在功能介绍上，而是完整走通一次可核对、可修改、可审核的实际任务。

## 四、录制前准备

1. 使用一个新的演示账号，不要展示真实邮箱、密码或企业未公开资料。
2. 清理浏览器下载目录和无关标签页，只保留应用页面。
3. 确认页面右上角显示“已连接”，协议为 `luyun-gateway/2.0`。
4. 准备第二审核账号，用于演示协作空间中的评论或审批；如果时间不足，可只展示邀请和审批入口。
5. 提前准备文件夹中的演示资料 `鲁香斋品牌档案.txt`；文件内容使用模拟数据。
6. 关闭系统通知，隐藏浏览器书签栏，使用纯色桌面背景。

## 六、备用镜头

如果现场网络不稳定，可以在主录屏之外补录以下镜头：

1. 网关断开后自动进入本地处理模式，页面仍能完成生成、风险检查和人工确认。
2. 修改文稿导入一份已有广告语，展示文件导入和风险语段定位。
3. 两个账号登录同一协作空间，展示邮箱邀请、评论和审批结果。
4. 打开一条内容护照链接，展示数字签名有效和内容哈希。
5. 展示账号数据导出和服务端数据删除确认，不实际执行删除。

## 七、录屏结束检查

- 输入、处理、输出三个阶段均有清楚画面。
- 至少展示一条事实的原文来源和编号。
- 至少展示一条高风险及其修改建议。
- 至少展示一次证据门禁或人工确认状态变化。
- 至少展示一份可编辑成果和一次广告词候选。
- 至少展示一次修改文稿的逐段建议。
- 至少展示一次审核记录或协作入口。
- 画面中没有真实密码、个人信息、企业机密或 API Key。
- 结尾明确说明原型模拟数据、人工审核边界和最终发布责任。

## 八、纯口播介绍版

老字号做新媒体，真正困难的地方不是写一段热闹的文案，而是把品牌历史、工艺、产品和受访内容整理成可以核对的事实，再把这些事实变成不同平台能用的内容。老字号叙事工坊面向山东老字号企业、非遗传承人和文创品牌的内容团队，把资料整理、事实提取、内容生成、风险检查和人工审核放进同一条工作流程。

使用时，企业先录入品牌资料和受访原话，系统为每条事实建立编号、来源位置和证据状态；随后通过 WebSocket 网关创建生成任务，输出品牌故事、内容日历、多平台文案和年轻化表达。生成结果会逐句检查医疗功效、虚假荣誉、绝对化宣传、无依据年份和无法验证工艺。只有关键事实得到确认、高风险表达得到处理，内容才能进入最终批准。所有 AI 原稿、人工修改稿、模型版本和审核记录都会保留，并可通过内容护照进行公开验证。

这件作品的价值不在于替代编辑，而是让编辑更快找到可靠资料，让品牌方更清楚地看到每一项对外表达的来源，也让每一次修改和审核都有记录可查。
